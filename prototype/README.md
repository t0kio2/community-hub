# Listing管理プロトタイプ

DBやRails APIを使用せず、1つのテナントが複数の滞在Listing（宿泊施設）を管理する設計をブラウザ操作で確認するためのプロトタイプです。

## 画面階層

最初に宿泊施設一覧を表示し、施設を選択して施設情報、Room Type、物理在庫、Rate Plan、日別設定、宿泊者プレビューおよび公開確認を操作する。新しい宿泊施設は空のListingとして追加し、施設ごとに設定を独立して保持する。Amenitiesマスターはテナント単位で共有する。

保存JSONは`tenant`、`amenities`、`stayListings[]`を持つ。旧版の単一Listing JSONが`localStorage`に残っている場合は、読み込み時にこのテナント集約形式へ変換する。ERやAPIの変更は行わない。

## 起動

リポジトリルートで静的HTTPサーバーを起動します。

```sh
python3 -m http.server 4173 --directory prototype
```

ブラウザで <http://localhost:4173> を開いてください。編集内容はブラウザの`localStorage`だけに保存されます。

- テナント向けListing管理: <http://localhost:4173>
- 一般ユーザー向け宿泊予約: <http://localhost:4173/guest.html>

## 停止

HTTPサーバーを起動したターミナルで`Ctrl+C`を押します。

起動したターミナルが分からない場合は、次のコマンドで4173番ポートを使用しているプロセスを停止できます。

```sh
lsof -ti :4173 | xargs kill
```

## テスト

```sh
cd prototype
npm test
```

## データを戻す

画面右上の「リセット」で`data/stay-listing.json`の初期状態へ戻せます。「JSONを書き出す」で現在の編集内容をダウンロードできます。

## 宿泊者プレビュー

「宿泊者プレビュー」では、チェックイン日、チェックアウト日、宿泊人数を指定し、現在のJSONから宿泊者向けの販売結果を組み立てます。DBや予約データは追加しません。

- Listing、Room Type、Rate PlanおよびRoom Type別料金の公開・有効状態を反映する
- 宿泊提供期間、定員、各宿泊日の物理在庫・販売上限を検証する
- 日別料金を優先し、各宿泊日の単価、数量、小計と滞在合計をRate Planごとに表示する
- 宿泊者が選択できるRoom TypeとRate Planだけを表示し、公開状態や非表示理由などの管理情報は表示しない
- Listingが下書きでも、公開後に宿泊者が見る画面として表示する

Listing管理内の宿泊者プレビューは既存予約、Room・Bedの期間停止、予約受付日時および画像ファイル本体を扱わない。予約作成と割り当ては、次項の一般ユーザー向け予約プロトタイプで検証する。

## 一般ユーザー向け予約

`guest.html`はテナント管理とは別の画面として、公開施設の選択、日程・人数検索、Room TypeとRate Planの選択、代表宿泊者・任意の同行者・メッセージ入力、予約内容確認、予約申請または即時予約完了を操作する。

予約作成時には現在の料金とキャンセル条件をスナップショットへ固定し、承認制は`requested`、即時確定は`confirmed`で保存する。貸切・個室はRoom、相部屋はBedを自動割り当てする。予約は`stayReservations[]`として同じlocalStorageへ保存する。

決済、追加料金・税、予約内容の変更、キャンセル、同行者の予約後編集は現在の未定義範囲なので、このユーザープロトタイプには含めない。
