 進める順番は以下を推奨します。

  1. 予約業務の未決事項を確定
      - 承認・拒否・キャンセルの理由と履歴
      - 予約内容を変更できる範囲
      - completed・無断不泊の扱い
      - 宿泊者情報の変更期限

  2. 予約管理プロトタイプ
      - 施設別ダッシュボード
      - 承認待ち予約
      - 予約一覧と絞り込み
      - 予約詳細
      - 承認・拒否
      - Room／Bed割り当ての確認・変更
      - キャンセル
      - 予約を反映したカレンダー

  3. プロトタイプで業務を点検
      - 即時予約と承認制の違い
      - 在庫の仮確保・確定・解放
      - 同時期の予約と部屋割り
      - スタッフが毎日見る情報
      - 操作履歴や通知の不足

  4. 点検結果を予約アーキテクチャとERへ反映

  最初は既存の予約設計をそのままJSON化し、代表的な予約データを数件用意するのがよいです。

  - requested：承認待ち
  - confirmed：確定済み
  - canceled：キャンセル済み
  - 貸切・個室のRoom割り当て
  - 相部屋のBed割り当て

  次に決めるべきなのは、予約管理画面の起点となる「テナントが毎日確認する予約ダッシュボード」の表示内容です。
