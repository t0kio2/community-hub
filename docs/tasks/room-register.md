
• 現在のERと業務仕様を基準に、依存関係が自然につながる初期設定フローと、運用開始後の常設メニューを分けて設計します。特にRoom Typeと物理Roomの登録順、料金プランとキャンセル条件の見せ方を整理します。


• おすすめは、「初回設定フロー」と「運用開始後の管理画面」を分ける構成です。現在のプロトタイプの方向性は概ねよいですが、依存関係と役割をもう少し明確にした方
  が迷いません。

  ## 初回設定の動線

  施設登録後は、通常の運営ダッシュボードではなく「販売開始までの設定」へ進ませます。

  1. 施設・宿泊設定
     ↓
  2. Room Type
     ↓
  3. 物理Room／Bed
     ↓
  4. 料金プラン・基本料金
     ↓
  5. 公開条件の確認
     ↓
  6. 公開

  Amenitiesは必須ではないため、Room Type設定や施設設定の中に含めます。

  施設登録完了
    → 「次にRoom Typeを登録してください」
    → Room Type登録完了
    → 「物理Roomを割り当ててください」
    → 在庫登録完了
    → 「料金プランを設定してください」
    → 公開確認

  各ステップで「後で設定」を許可し、常に下書き保存できるようにします。

  ## 常設ナビゲーション

  運用開始後は施設管理画面に次のメニューを置くのがよいです。

  概要
  施設設定
  Room Type
  Room／Bed
  料金プラン
  販売カレンダー
  予約

  「Amenities」と「キャンセルポリシー」は独立したトップメニューにしない方が分かりやすいです。

  - 施設Amenities：施設設定内
  - Room Type Amenities：Room Type編集内
  - キャンセルポリシー：料金プラン編集内
  - 日別料金・販売上限：販売カレンダー

  ## Room Type画面

  Room Typeは「利用者が選ぶ商品分類」と説明します。

  一覧：

  Room Type
  ├─ 女性専用ドミトリー
  ├─ シングル
  ├─ ダブル
  └─ 一棟貸し

  登録・編集項目：

  - 名称
  - 利用形態
      - 一棟貸し
      - 個室
      - 相部屋

  - 1販売単位の定員
  - 説明
  - 公開画像
  - Room Type Amenities
  - 状態

  利用形態を選ぶと説明を切り替えます。

  個室
  1つのRoomを1販売単位として販売します。

  相部屋
  Room内のBedを1販売単位として販売します。

  一棟貸し
  一棟を表すRoomを1販売単位として販売します。

  shared_roomを選んだ場合はcapacity = 1を自動設定し、編集不可にするのがよいです。

  保存後のCTAは次です。

  「女性専用ドミトリー」を登録しました
  次に、このRoom Typeへ物理RoomとBedを登録してください
  [Room／Bedを登録]

  ## 物理Room／Bed画面

  一覧はテーブル形式が適しています。

   管理名         Room Type             構成          状態    停止期間
  ━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━  ━━━━━━  ━━━━━━━━━━━━
   101号室        シングル              Room販売      有効    なし
  ─────────────  ────────────────────  ────────────  ──────  ────────────
   201号室        ダブル                Room販売      有効    8/20〜8/22
  ─────────────  ────────────────────  ────────────  ──────  ────────────
   ドミトリーA    女性専用ドミトリー    8 Beds        有効    なし
  ─────────────  ────────────────────  ────────────  ──────  ────────────
   旧館201        未分類                販売対象外    停止    なし

  Room登録項目：

  - 管理名
  - 所属Room Type
  - 有効／停止
  - 管理メモ

  所属Room Typeは任意にして、「未分類」も選べるようにします。

  相部屋へ紐づけた場合だけBed管理欄を表示します。

  ドミトリーA
  ├─ A-1 有効
  ├─ A-2 有効
  ├─ A-3 停止
  └─ A-4 有効

  Bedの一括追加もあると便利です。

  Bed数: 8
  接頭辞: A-
  → A-1〜A-8を作成

  個室・一棟貸しではBed欄を表示しません。

  物理在庫を先に台帳登録するユースケースもあるため、Room Type未登録でもRoomを登録できる動線を残します。

  [Room Typeを先に登録]
  [未分類Roomとして登録]

  初回設定ではRoom Typeを先に案内しますが、データモデル上の柔軟性は維持します。

  Amenitiesは自由入力欄ではなく、カテゴリ別チェックボックスにします。

  設備を検索 [                    ]

  通信
  ☑ Wi-Fi

  空調
  ☑ エアコン
  □ 暖房

  浴室
  ☑ 専用バス
  □ 共用バス

  アクセシビリティ
  □ エレベーター
  □ 車椅子対応

  施設Amenitiesは「施設設定」、Room Type Amenitiesは「Room Type編集」で選択します。

  テナント固有Amenitiesは同じ画面から追加できます。

  [＋ 独自設備を追加]

  対象: 施設
  カテゴリ: サービス

  ただし、入力欄へ自由入力してそのまま関連付けるのではなく、必ずAmenityレコードを作ってから選択状態にします。

  ## 料金プラン画面

  画面は左にプラン一覧、右に編集内容を置く構成が合っています。

  料金プラン
  ├─ 素泊まり
  ├─ 朝食・夕食付き
  └─ 返金不可・素泊まり

  プラン編集項目：

  - プラン名
  - 説明
  - 食事条件
  - キャンセル条件
  - 状態
  - Room Type別料金

  Room Type別料金は表形式にします。

  ━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━  ━━━━━━  ━━━━━━━━━━

  ────────────────────  ────────────  ──────  ──────────

  ## キャンセルポリシー

  現行仕様ではstandard / non_refundableの固定テンプレートなので、独立した管理画面は不要です。

  料金プラン内で選択します。

  キャンセル条件

  ● 標準キャンセル
    7日前から20%
    2日前から50%
    前日から80%
    当日・無断不泊100%

  ○ 返金不可
    予約確定後100%

  non_refundableを選んだときは確認表示を入れます。

  このプランは予約確定後に返金できません。
  利用者にも返金不可として表示されます。

  将来、テナントが期限や料率を自由設定する要件ができた段階で、キャンセルポリシーマスターを独立させれば十分です。

  ## 販売カレンダー

  日別料金と販売上限は、料金プラン画面ではなく専用カレンダーに分けます。

  2026年8月

  Room Type: ダブル
  Rate Plan: 素泊まり

          10     11     12     13
  料金   ¥9,000 ¥9,000 ¥12,000 ¥12,000
  上限      5      5       3       0

  一括設定：

  期間: 8/1〜8/31
  曜日: 金・土
  料金: 12,000円
  販売上限: 3

  ここでは次を区別して表示します。

  - 基本料金
  - 日別上書き料金
  - 物理在庫数
  - 販売上限
  - 予約済み数
  - 予約可能数

  ## 推奨する実装順

  画面実装も依存関係に沿って進めるのが安全です。

  1. 施設管理ナビゲーションと公開準備画面
  2. Room Type CRUD
  3. Room／Bed CRUD
  4. 施設・Room Type Amenities
  5. Rate Plan CRUD
  6. Room Type別基本料金
  7. 固定キャンセル条件の表示
  8. 日別料金
  9. 日別販売上限
  10. 公開判定

  現在あるプロトタイプは再利用できますが、「施設登録後にどこへ進むか」「不足項目から各設定へ移動するリンク」「日別販売管理を料金プランから分離する」の3点を
  特に改善するのがよいです。
