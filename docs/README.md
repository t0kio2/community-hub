# ドキュメント構成

## 正本

- `architecture/`: 業務仕様、状態遷移、各機能の責務
- `er/`: テーブル、関連、外部キー、データ制約
- `operations/`: テナントや運営者が行う業務の正式な業務定義

アーキテクチャとERに同じ内容を重複記載せず、業務判断は`architecture/`、データ構造は`er/`を正本とする。

## その他の文書

- `operations/stay-tenant-operations.md`: テナントが行う宿泊業務の正式な業務定義
- `listing-prototype-design.md`: DBを使用しないListingプロトタイプの構成
- `setup.md`: 開発環境のセットアップ
- `testing.md`: テスト実行方法
- `codex-skills.md`: リポジトリ固有Skillの利用方法

その他のルート直下文書は、実装固有の設計書として残している。今後、内容を正本へ統合できたものから削除または適切なサブディレクトリへ移動する。

## 整理方針

次の文書は削除対象とする。

- 一時的な次回作業メモ
- `architecture/`と`er/`に置き換えられ、他文書から参照されていない旧設計
- 完了済みのディレクトリ改名など、現在の構成そのものから確認できる作業計画

実装済み機能の設計書は、正本との重複とコード上の現状を確認してから削除する。
